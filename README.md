# Landscape Modeling of Dadu River Drainage Reorganization

This repository contains the Badlands landscape-evolution model setups used in the study *Landscape Modeling of the Dadu River Drainage Reorganization in Southeast Tibet*. The experiments evaluate the effects of branching fault-system kinematics, localized uplift, a paleo-lake/barrier scenario, and their integrated combination on Dadu River drainage evolution.

## Overview

All simulations use [Badlands](https://github.com/badlands-model/badlands) and run for 5 Ma. The supplied Python batch runners generate the tectonic and precipitation input fields, update the corresponding Badlands XML file for each experiment, execute Badlands, and save a copy of the inputs used with each output.

The four model directories are:

| Directory | Experiment | Batch entry point | Parameter sweep |
| --- | --- | --- | --- |
| `model1/` | Fault-kinematics experiment | `run_model1_batch.py` | Three Daliangshan Fault rake values (16°, 33°, 55°) × three erodibilities (`1e-6`, `2e-6`, `3e-6`): 9 runs. |
| `model2/` | Localized uplift experiment | `run_model2_batch.py` | Three horizontal- and three vertical-arm uplift rates × three erodibilities: 27 runs. |
| `model3/` | Barrier uplift and downstream/base-level-lowering experiment | `run_model3_batch.py` | Three barrier-uplift magnitudes (300, 400, 500 m/Myr) × three erodibilities: 9 runs. |
| `finalmodel/` | Integrated model | `run_model1_rake55_plus_uplift_model3_dam_capture_batch1.py` | One configurable combined scenario per invocation; an optional Slurm parameter sweep is provided in `river.sbatch`. |

`initiallandscape/` contains the starting topography and Badlands restart setup shared by the experiments.

## Repository layout

```text
allcode/
├── initiallandscape/    # Initial topography and restart setup
├── model1/              # Fault-kinematics parameter sweep
├── model2/              # Localized uplift parameter sweep
├── model3/              # Barrier/base-level parameter sweep
├── finalmodel/          # Integrated model and Slurm submission script
└── README.md
```

Within each model directory:

- `Dadu_run.py` loads the Badlands XML configuration and runs the model to 5 Ma.
- `fault_displacement_v4.py` constructs the Xianshuihe, Anninghe, and Daliangshan fault displacement fields.
- `uplift_with_noise.py` generates the localized uplift fields where applicable.
- The XML file defines the Badlands grid, restart, tectonic events, precipitation, erosion law, and output location.
- `run_*_batch.py` is the preferred entry point for the parameter sweep.

## Software requirements

- Python 3
- Badlands
- NumPy
- SciPy
- Matplotlib

The original Slurm script activates a Conda environment named `uw-2.17`. This name is not a complete dependency specification; users should create a Python environment containing a Badlands version compatible with the XML format, then record its exact package versions before publishing a formal release.

## Climate forcing

The three model experiments use the same three alternative precipitation settings:

1. **Uniform precipitation.** Precipitation is set to a spatially uniform value of **1 m/yr**.
2. **Topographic (orographic) precipitation.** Precipitation is read from the spatial map **`participe.csv`**, which is generated by the batch scripts.
3. **Time-varying monsoon precipitation.** Precipitation is represented by **28 rainfall events** in `model3/model3monsoon.xml`. The events specify the precipitation values and their time intervals over the 5 Ma simulation.

These three climate settings are applicable to **Model 1, Model 2, and Model 3**. The supplied Model 3 batch runner currently looks for `model3.xml`, whereas the monsoon configuration is named `model3monsoon.xml`; use that monsoon file consistently by renaming/copying it to `model3.xml` or by updating the two Model 3 Python scripts.

The integrated model additionally permits local precipitation adjustments, including a Gongga precipitation reduction (`--gongga-rain-factor`) and a Gaussian enhancement near the river bend (`--bend-rain-factor`, `--bend-rain-sigma-x`, and `--bend-rain-sigma-y`).

## Important preparation before running

The model configurations reference a Badlands restart directory named `initiallandscape` at restart step `20`. Generate or provide this restart output before running any of the four experiments, and then set the `<rfolder>` element in each XML file to its actual location.

Two configuration details in the supplied files must also be addressed in a fresh clone:

1. `model2/Daduhejif.xml` and `model3/model3monsoon.xml` specify `initopo.csv`, but that file is not currently present in those two directories. Either copy `initiallandscape/initopo.csv` into each directory or change `<demfile>` to the appropriate relative path.
2. `model3/Dadu_run.py` and `model3/run_model3_batch.py` expect an XML file named `model3.xml`, whereas this repository currently provides `model3monsoon.xml`. Before running Model 3, copy or rename that file to `model3.xml`, or consistently update both Python scripts to use `model3monsoon.xml`.

In addition, `finalmodel/Daduhejif.xml` contains an author-specific absolute restart path. Replace it with the local or HPC path to your generated `initiallandscape` restart output.

## Running the models

Run commands from the corresponding model directory. Test the planned actions first with `--dry-run`; this does not generate files or start Badlands.

### Model 1: fault kinematics

```bash
cd model1
python run_model1_batch.py --dry-run
python run_model1_batch.py
```

The script modifies a temporary copy of `fault_displacement_v4.py` for each Daliangshan Fault rake, generates `newtec*.csv` and precipitation fields, and restores `Daduhejif.xml` when it finishes.

### Model 2: localized uplift

```bash
cd model2
python run_model2_batch.py --dry-run
python run_model2_batch.py
```

This script regenerates the fault field with a pure strike-slip Daliangshan Fault, creates noisy Gongga and Tuowu uplift fields, and runs 27 uplift/erodibility combinations.

### Model 3: barrier and base-level change

```bash
cd model3
cp model3monsoon.xml model3.xml   # needed with the files currently supplied
python run_model3_batch.py --dry-run
python run_model3_batch.py
```

The batch script creates tectonic input fields for three barrier heights and applies a localized negative-displacement field to represent the downstream/base-level change.

### Integrated model

```bash
cd finalmodel
python run_model1_rake55_plus_uplift_model3_dam_capture_batch1.py \
  --settings-dir . --uplift-dir . --model-dir . --dry-run

python run_model1_rake55_plus_uplift_model3_dam_capture_batch1.py \
  --settings-dir . --uplift-dir . --model-dir .
```

The integrated workflow combines fault displacement, Gongga/Tuowu uplift, a right-side dam uplift, a Minjiang subsidence corridor, and a spatially varying precipitation field. Its four tectonic stages are 0–1 Ma, 1–2 Ma, 2–3.5 Ma, and 3.5–5 Ma.

The script filename and top-of-file description are legacy names: the current code sets the Daliangshan Fault rake to **40°** (`RAKE = (3, 40.0)`). This value should be checked against the manuscript before the repository is released.

### HPC/Slurm sweep

`finalmodel/river.sbatch` launches 27 integrated-model cases spanning three river-bend precipitation factors and three values each of the x- and y-direction Gaussian widths. Update `TEMPLATE_DIR`, `RUN_ROOT`, Conda environment name, and Slurm resource settings for your cluster before submission.

```bash
cd finalmodel
sbatch river.sbatch
```

## Outputs

The batch scripts create output directories named after their parameter combinations (for example, `model1_1-1`, `model2_1-1-1`, and `model3_1-1`) and write run logs to `batch_logs/`. Badlands outputs can be large; they are intentionally not included in this code repository. Each completed run stores a copy of the XML configuration and generated forcing files used for that case.

To rerun an existing case, use exactly one of:

```bash
python run_model1_batch.py --skip-existing
python run_model1_batch.py --overwrite
```

`--skip-existing` retains existing results; `--overwrite` deletes matching output directories before rerunning. Use `--overwrite` only when you intend to replace generated results.

## What to include in the GitHub repository

Commit the Python scripts, XML files, `initopo.csv` inputs required by the XML files, this README, and a `LICENSE`. Do not commit generated output directories, `batch_logs/`, Badlands `h5/` outputs, temporary batch scripts beginning with `_`, or `.DS_Store` files. A `.gitignore` should exclude those generated files.
